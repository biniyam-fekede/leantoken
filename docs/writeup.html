I tried to stop my AI from building towers

I gave an AI coding agent a rule to write less code. Then I measured what that actually did.

AI coding agents sometimes over-build. Ask for a date formatted nicely and you get a hand-written table of twelve month names. Ask to copy an object and you get a 20-line recursive cloning function. All of it works, but none of it was necessary.

LeanToken is a small plugin that gives the agent one checklist to walk through before it writes anything:

  1. Is this change needed at all?
  2. Does the codebase already have it?
  3. Is it built into the language?
  4. Is it built into the platform?
  5. Is a library already installed?
  6. Does it need a new abstraction?
  7. Only then, write the smallest change that works.

The agent also has to say which step it stopped at, so you can see why it chose a solution, not just what it wrote.

How it was measured

  • 27 small coding tasks, each aimed at one step of the checklist.
  • Claude Sonnet ran each task 3 times with LeanToken and 3 times without, from identical starting code. That's 162 runs.
  • Hidden tests were added only after the agent finished, so it couldn't read or game them.
  • Every run recorded lines changed, tokens, cost, time, and new packages.

What happened

On a typical task, nothing changed. The median task came out with the same amount of code either way. Modern models are already fairly lean on small, clearly worded tasks.

When a built-in existed, the difference was big.

TaskWithoutWithWhat it used
Deep-copy settings122structuredClone

Generate an ID42crypto.randomUUID

Shorter code was also more correct. On the query-string task, the agent without LeanToken wrote its own parser and forgot that + means a space in URLs. It failed the hidden tests in 2 of 3 runs. With LeanToken it used the built-in URLSearchParams and passed every time. Overall, tests passed in 96% of runs with LeanToken and 95% without.

Being lean wasn't free. Thinking through the checklist costs tokens. On the median task, LeanToken used 7% more output tokens, cost 5% more, and took 13% longer. On a few tasks it wrote slightly more code: the rate limiter went from 12 lines to 14.

The decision log worked every time. The agent recorded which step it stopped at in 81 of 81 runs. "Built into the language" was the most common answer.

What I got wrong

One task asked for a SHA-256 hash, and both versions failed it the same way. The agents wrote an async function, but the hidden test expected a synchronous one, and the task never said which. That's the benchmark's fault, not the agent's.

Takeaway. A "write less code" rule isn't a magic cost cutter for small tasks, because today's models already avoid most obvious bloat. What it does is push the agent toward built-ins at exactly the moments when hand-rolled code is both longer and buggier. The price is a few percent more tokens per task.

What's next

Removing one checklist step at a time to see which ones actually matter, and trying bigger, messier tasks where the towers should get taller.
